# 源程序与文档鉴别材料生成方案（草稿）

拟软件全称：AccelSched 异构算力资源优化调度软件 V1.0；包版本1.0.0。此方案不提交材料，不生成登记号，不代表已满足受理要求。

## 官方依据与口径

依据[国家版权局《计算机软件著作权登记办法》](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)第10条，通常程序和选用文档分别取开头及末尾各连续30页；不足60页应交全部。常规程序/文档每页最低行数分别为50/30，特定情况按正式要求处理。第12条另列例外交存方式；不能把例外自行当成规避代码/权属审查的授权。

本工具生成源程序文本草稿及映射；正式A4排版、页眉/页码、短末页及文档行数需人工核对。它不把Markdown源文件行数当作排版后的文档页数，不插空行/重复代码凑页数，不伪造界面或源行，不自动宣称合规。

## 冻结与范围

1. 等待 Architect T2 与权利人放行；冻结最终40位 commit/tree、LICENSE、pyproject版本、功能范围与设计文档。不要把准备日期当完成/发表日期。
2. 生成范围从该 commit 的 `py-modules` 和 `packages` 读取：十个核心模块与 examples 的项目Python源文件。顺序是模块声明顺序，再按包路径排序。该范围对应V1安装包功能；不是声称所有Git文件都具有相同法律权属。
3. 排除第三方源码/二进制、site-packages、GPU研究Probe、测试、生成工具、trace/restricted数据、身份文件和密钥。Git来源不替代权属核查。
4. 保留完整原始源码；草稿每页取50个原逻辑行，保留原有空行，不增补。最后不足50行时标记人工审核；代码文本不插入伪源码页眉，页眉信息在manifest里，正式排版再添加。

## 可重复命令

从源码根目录，用实际冻结的40位提交替换占位符，输出必须在Git检出目录外、目录不得已存在：

```bash
python tools/source_deposit.py --repo . --commit <FROZEN_40_HEX_SHA> --output ../deposit-draft-v1
```

工具使用 `git show` 读取冻结 blob 而非未提交工作树；校验普通文件、版本、明确源范围；不下载依赖。结果包括选中的 `source-NNN.txt` 与 manifest.json：原文件blob/SHA256/字节数、commit/tree、每页SHA和逐行原路径/行号、全页数和页序。大于60页时保留前30/后30；否则全部。逻辑行渲染为LF，原始blob哈希另存，不能将渲染页SHA冒作原blobSHA。

相同commit在两个仓库外目录导出，所有页面和manifest应字节一致；证据应记录两次结果和完整文件哈希。工具状态恒为 DRAFT_NOT_FILING_APPROVAL。不得在输出上手工补行；如修改软件/文档，应形成新提交并重新冻结与导出。

建议选用[中文软件设计说明书](software-design.zh-CN.md)，覆盖功能、架构、输入/输出、流程、安装和验证。按同一名称/版本排版为PDF，核对实际分页及通常每页30行规则；不足60页交全部。保留完整原文和PDF的SHA，前后页选择以真实排版为准。源码与文档页数分别计算，不混合凑60页。

真实CLI输出可取自冻结候选wheel的smoke日志，并写明环境、输入SHA和运行结果；不制作未运行的GUI截图。申请人身份/授权材料私下处理。正式表单、名称拼写、例外、补正与提交形式需向中国版权保护中心确认；本仓库不包含正式申请人的证件或签章。
